**AD-881 shipped (2026-06-05; Wave 239).** Seventh AD of the Quartermaster-hardening epic (#847) — detect live-but-stalled assignees. The reconciler reclaimed only items whose assignee was **absent** from the registry (`WorkItemReconciler.resolve_live_agent` returns `None`); an assignee that is **live but silently stuck** (claimed an item, made no board progress) was never reclaimed. AD-881 adds a **config-gated, default-off (0)** coarse staleness signal. Verify-first finding (documented in DECISIONS.md): `updated_at` is **last board-mutation, not a heartbeat** — `WorkItemStore.update_work_item` (`src/probos/workforce.py`) sets `updated_at = time.time()` on every update, so it advances on claim / status / assignment changes routed through the board, but **not** from agent-internal "still working" progress that never touches the board. So `now - updated_at` is a coarse "claimed long ago, never progressed" signal, not a true liveness probe — hence default-off and no heartbeat plumbing added (out of scope). Implementation keeps `WorkItemReconciler` pure: the sweep owns the clock + threshold and passes a precomputed `is_stalled` boolean into `classify(wi, *, is_dispatchable, is_stalled=False)` (`src/probos/cognitive/work_reconciler.py`); when `is_stalled` and the assignee is live and `status == "in_progress"`, classify returns `clear_and_reroute` with `reason="stalled"` instead of the usual skip. In the shared `_process_item` (`src/probos/agents/quartermaster.py`, so the rule applies to both periodic `reconcile()` and reactive `reconcile_for_agent()`), the sweep computes `is_stalled = _stall_timeout_seconds > 0 and status == "in_progress" and float(updated_at) < time.time() - _stall_timeout_seconds` (**strict `<`** older-than) and increments `counts["stalled"]` when a `clear_and_reroute` carries `reason="stalled"`. A stall-reroute flows through the **AD-877 attempt guard** exactly like any other clear_and_reroute — it increments `reconcile_attempts`, honours backoff, and quarantines at the threshold — so a chronically stalled item can't thrash. New bounded config on `WorkBoardReconcilerConfig` (`src/probos/config.py`): `stall_timeout_seconds: int = Field(default=0, ge=0, le=86400)` (`0` = disabled, transitional default-off — conv #14), injected onto the live agent as `agent._stall_timeout_seconds` in `startup/finalize.py` `_wire_board_reconciler`, with a matching `stall_timeout_seconds=0` constructor kwarg. +6 pytest (`tests/test_ad881_stall_detection.py`, real `WorkItemStore` + real `AgentRegistry` per BF-287 so `resolve_live_agent` resolves a registered live agent; `updated_at` seeded via `create_work_item`): disabled (0) never reclaims a live-old item, enabled reroutes an old live in_progress item with `counts['stalled']++`, a fresh item is not reclaimed, an absent assignee takes the normal absent path (not double-counted as stalled), a stall-reroute quarantines at the AD-877 threshold, and the strict `<` boundary is not stalled. The AD-875 empty-board exact-dict test gained the always-present `stalled` key (obsolete-contract guard). One commit.
