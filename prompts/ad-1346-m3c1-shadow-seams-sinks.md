## 1. Problem

- `AdmissionService.shadow` (`src/probos/admission/service.py:88-106`) has no caller in `src` (Absence Verified). #1601's evidence 1 (coverage), 3 (classified would-refuse), 4 (parity with today's checks) and 12 (a golden test) all need the stop-check sites to call it.
- `STOP_CHECK_SITES` (`tests/fixtures/ad1343_seam_registry.py:21-39`) holds 16 entries in 16 different functions. The slice plan counted 15; AD-1347 S1 added `AgentWorkService._requester_stop` (`:37-38`).
- Today's outcome is not a parameter. The recorder samples would-refuse verdicts only (`recorder.py:119-125`). An admit that disagrees with a site's refusal is therefore invisible, and it is the class of disagreement M4 must rule on.
- The M3b register leaves three items to this slice:
  - R1: a flusher that ends with an exception stops writing (`recorder.py:145-151`);
  - R6: where the recorder stops relative to the seams (`shutdown.py:1490-1503`);
  - R7: today's outcome and `admission.shadow_enabled`.
- F-212 is binding here: `shadow`'s log call has no guard of its own (`service.py:98-105`), so a handler whose `emit` raises escapes `shadow`. The M3a reviewer reproduced it (#1604, the consult-2 comment).
- Hidden pins:
  - the seam census (`tests/test_ad1343_stop_seam_inventory.py`);
  - T14's per-file allowlist (`tests/test_ad1346_admission_service.py:70-98`) and T16's consumer census (`:538-558`);

## 2. Solution

- **`probos.admission.seam.shadow_at(service, *, presented_id, work_kind, seam, origin, origin_id, refused)`.** It calls `service.shadow(..., today_outcome=...)` only on an exact `AdmissionService`. It maps `refused is True` to `refuse` and anything else to `admit`, and returns None.
- **`AdmissionService.shadow`:**
  - takes `today_outcome: str | None = None` and checks it before deciding;
  - passes it to `ShadowRecorder.offer`;
  - guards its log call (F-212);
  - returns None at once after `close()`.
- **`ShadowRecorder.offer(verdict, elapsed_ns, today_outcome=None)`** counts each verdict it aggregates with a today's outcome by (hour, work kind, seam, today's outcome, outcome, reason code). It keeps disagreements in a bounded buffer. The flusher counts an `Exception` from a flush as `flush_errors` and keeps running.
- **`admission_shadow.db`** gains two tables under schema version 1:
  - `shadow_parity`: by UTC day, pruned with the aggregates;
  - `shadow_disagreements`: the newest 1,000 rows.
- **The report** gains `parity_by_work_kind` and `disagreement_samples`.
- **`admission.shadow_enabled`** (default true) is read once in `start`. When false, no shadow store, recorder or service is built.
- **Shutdown** closes the service, then flushes the recorder, then stops the store.
- **The four sinks** each call `shadow_at` once after their check (the run entry once per path). The tool sink reaches the service through `ToolRegistry.set_admission`.
- **The census guard** requires every stop check to be in `SHADOW_SITES` or in `SHADOW_PENDING`. It pins each statement's count, keywords and place.

## 3. Decisions (numbered after M3b's D38 to D53)

- **D54 Split by seam family.** This slice covers the machinery and the four sinks. M3c2 covers the six routing seams (proactive, Ward Room, DM route, group fan-out, the Captain's browser ACK, the inline browser action). M3c3 covers delegation, the four crew sites and agent work.
  - Reason: the 16 functions reach the stop in four ways (the runtime attribute, a late-bound setter, constructor injection, an injected gate).
  - Rejected: one slice (too large for one review round); machinery alone (a library with no caller, and the golden test needs seams).
- **D55 Statements, place and reach.**
  - **Count.** 16 entries in 16 functions. M3c1 adds 5 calls at 4 entries: one each in `CognitiveAgent.handle_intent`, `CognitiveAgent.handle_consultation_request` and `ToolRegistry.check_and_invoke`, and two in `WorkItemAgenticExecutor.run`. `refuse_new_run` raises `AgentStopped`, so the statement for the refused path sits in an `except AgentStopped:` before a bare `raise`, and the statement for the admitted path follows the call.
  - **Place.** Each statement comes after its check's result is known and before the site acts on it, with no await between (census test 9b).
  - **Reach.** A site reaches the service the way it reaches its stop gate: from the runtime (`getattr(..., "admission_service", None)`) where it reads `agent_stops` from the runtime, and through a late-bound setter (`ToolRegistry.set_admission`, beside `set_stop_gate`) at the tool sink.
  - Rejected: a hook in `AgentStopService.refusal`. #1604 property 10 has M4 replace each seam's call and not the gate object, and `agent_stop` would have to import `probos.admission` (a cycle). Also rejected: a service locator (#1604, Do Not Build).
- **D56 Each site's `WorkRequest`.**

  | Site | work_kind | seam | origin | origin_id | presented_id | today's outcome |
  |---|---|---|---|---|---|---|
  | `handle_intent` | `intent` | `SEAM_INTENT` | `system` | `getattr(intent, "intent", "")` | `self.id` | `refuse` when `_stops.refusal(...)` returned a record |
  | `handle_consultation_request` | `consultation` | `SEAM_CONSULTATION` | `agent` | `getattr(request, "requester_id", "")` | `self.id` | the same |
  | `check_and_invoke` | `tool_call` | `SEAM_TOOL` | `agent` | `agent_id` | `agent_id` | `refuse` when `tool_refusal` returned a result |
  | `WorkItemAgenticExecutor.run` | `agentic_run` | `SEAM_AGENTIC_RUN` | `system` | `"agentic_run"` | `agent_id` | `refuse` on the `AgentStopped` path, `admit` after the call returned |

  - Reason: each value is the most specific true one the site holds. `IntentMessage` carries no sender (`types.py:58-68`), so the intent sink records the intent's name.
  - The intent and consultation statements run only inside the site's `if isinstance(_stops, AgentStopService):`. A runtime without that service has no `AdmissionService` either, because its constructor refuses one (`service.py:46-47`, and the runtime's `except Exception`).
  - Rejected: `captain` for a DM at the intent sink, because the DM route's own seam (M3c2) knows the Captain asked.
- **D57 Today's outcome and the signature.**
  - `TODAY_OUTCOMES = ("admit", "refuse")` is appended to the taxonomy.
  - `shadow(*, presented_id, work_kind, seam, origin, origin_id, today_outcome: str | None = None)`. None records no parity row.
  - A `today_outcome` that is not None and is not an exact `str` in `TODAY_OUTCOMES` raises `ValueError` inside `shadow`'s `try`, before the decision, and is counted in `failures` (P7, SV-3).
  - `offer` gains `today_outcome: str | None = None` (positional-or-keyword, default None). `shadow` passes it by keyword.
  - Rejected: a required parameter. A missing keyword raises `TypeError` at the call, outside `shadow`'s `try`.
- **D58 Disagreement, persistence and compatibility.**
  - **Rule.** `is_disagreement(outcome, today) = (outcome == "would_refuse") != (today == "refuse")` (`recorder.py`).
  - **Failures are not disagreements.** A shadow failure is counted in `failures`. Counting it as a disagreement would mix defects into the parity count.
  - **Parity rows.** Every verdict the recorder aggregates with a today's outcome is counted for `shadow_parity`, PK (day, work kind, seam, today's outcome, outcome, reason code). One day holds at most `len(WORK_KINDS) * len(SEAMS) * len(TODAY_OUTCOMES) * len(REASON_CODES)` rows for the verdicts `decide` builds: 1,056 with this tree's vocabularies, because an admit always carries `admitted` (`record.py:95-96`). `prune` deletes parity days before the last `AGGREGATE_RETENTION_DAYS`. P13 pins that 35 such days stay below `AGGREGATE_ROW_LIMIT`. A wall clock that steps back can hold more days (M3b R2).
  - **Disagreement samples.** Disagreements are kept, within `DISAGREEMENT_BUFFER_LIMIT = DISAGREEMENT_RING_SIZE = 1_000` pending, in `shadow_disagreements` (today's outcome beside the `to_dict` JSON). Each `write_batch` that adds one keeps the newest 1,000. A sample beyond the buffer is counted in memory as `disagreement_samples_dropped`. A failed write puts back at most the buffer's worth and counts the rest the same way.
  - **Bound on pending parity keys.** They are at most twice the pending aggregate keys, on every path, for the values `shadow` passes. Both are counted in the same `offer`, detached together in `_flush`, written in one transaction and put back together in `_restore`. The aggregate keys can exceed `PENDING_KEY_LIMIT` after a failed write (M3b R10), and so can the parity keys.
  - **Schema.** Both tables are additive, so `SCHEMA_VERSION` stays 1 (`CREATE TABLE IF NOT EXISTS` in `_SCHEMA`, which `start` runs on any version-1 file).
  - **Compatibility.** A file the M3b build wrote opens here with its rows unchanged (P6). The M3b build's `start` accepts a file this build wrote, because it checks only the version row and creates only its own three tables (`store.py:192-211`, read).
  - Rejected:
    - version 2: a reverted build would refuse the file and lose evidence;
    - a column on `shadow_aggregates` or `shadow_samples`: it changes a key or needs `ALTER`, so it is not additive;
    - a column on `shadow_markers` for the drops: `ALTER` again.
- **D59 F-212 and R1.**
  - **`shadow`.** Its `except Exception` wraps the log call in `try`/`except Exception: pass`. No `Exception` leaves `shadow`; a `BaseException` that is not an `Exception` propagates. The failure is already counted in `failures`. Reason: from M3c1, `shadow` runs on the tool and intent paths, where an escaping `Exception` would break #1604 property 6.
  - **The flusher (R1).** `_run` catches an `Exception` from `_flush`, counts `flush_errors` and goes on to the next tick. It does not log, because the log call may be what raised. Both log calls in `_flush` run after any batch it detached was put back (`_restore` before `_failed`). A `BaseException` that is not an `Exception` ends the task.
  - Rejected: guarding every log call in the package. `stop`'s final warnings and the runtime's two warnings stay unguarded (register R15).
- **D60 `shadow_at`.**
  - It checks the exact type `type(service) is AdmissionService`, so None, `MagicMock(spec=AdmissionService)` and any other object are passed over (P10).
  - Its own work is that check and one call whose keywords are `shadow`'s (T13 pins the signature). It raises no `Exception`; a `BaseException` that is not an `Exception` propagates.
  - The argument expressions at the sites are local names, constants, `x is not None`, and `getattr` with a default on objects the site already holds.
  - It sits in the `_ALLOWED_IMPORTS` group of T14 (no await, lock, file or connection call).
  - Rejected: an inline `if x is not None: x.shadow(...)` at each site. It would call a test double that holds the attribute.
- **D61 `close()` and the shutdown order (R6).**
  - `AdmissionService.close()` sets `_closed`. A later `shadow` returns None before its `try`, deciding, counting and offering nothing. `decide` is unaffected.
  - Shutdown calls it immediately before the recorder's stop step, as a plain statement read with `getattr` (it is synchronous and only sets a flag). Then the recorder's last flush, then the store.
  - Shadow coverage therefore ends at that point in Phase 2. Each seam's own stop check is unaffected, and the evidence leaves out the rest of a shutdown (register R17).
  - A holder of the service other than the runtime (the tool sink, from M3) goes inert in the same call. Nothing after the close decides over the identity registry the shutdown stops next.
  - Rejected: moving the recorder's stop after the pools. `decide` reads the identity facade, whose registry stops before the pools (`shutdown.py:1505-1511`), and changing AD-441's order is outside M3c.
- **D62 `admission.shadow_enabled`.**
  - A new `AdmissionConfig(BaseModel)` with `shadow_enabled: bool = True`, as `SystemConfig.admission`.
  - **Default true:** shadow mode never blocks and never charges, so it is inside D2 (the Option A comment told the Captain so). The switch is the rollback lever.
  - **Profile qualification:** `check_config_profiles.py` classifies only booleans that default to false (`:149-170`), so it needs no manifest row.
  - **When it is read:** once, in `ProbOSRuntime.start`, as `self.config.agent_work.enabled` is (`runtime.py:3503`). When false, neither the store-and-recorder block nor the service block runs, one INFO line says so, and the three attributes keep their `__init__` None.
  - **A running recorder:** turning the switch off after start changes nothing until the next start.
  - **What moves:** the config facade baseline (`check_config_facade.py --update-baseline`) and the config reference (`gen_config_reference.py`), both regenerated in M2.
- **D63 The golden test (#1604 property 12).**
  - G2 boots twice on `tmp_path`, with `admission.shadow_enabled` true and then false. Each boot uses `SystemConfig()` with the naming ceremony, the proactive loop and QA off, and `MockLLMClient`, as the M3a boot tests do (D33). There is no vessel, the network is untouched (NATS is off under `tests/conftest.py`'s default), and the data directory is under `tmp_path`.
  - On each boot it drives the four sinks: once with no order (an unhandled targeted intent, an unknown tool, an incomplete owned-steps binding at the run entry) and once under a Captain's stop (all four).
  - It asserts that the canonical JSON of the answers is byte-identical, once the order's id, its start time and the agent's id are replaced, and that the refusals counted under the order are one per seam on both boots.
  - "With the shadow service idle" is read as "built or not built". Rejected: comparing with the pre-M3c tree, which one test cannot run.
- **D64 Cost of one call.**
  - It awaits nothing: T14's AST check over `service.py` and `seam.py`, and the recorder test R2's over `offer`.
  - On a slot-id key it does a constant number of dictionary operations: `IdentityService.resolve` takes the `_slot_cache` path (`identity.py:787-794`), `stop_for` reads one dict, `offer` updates at most five dicts.
  - A DID or certificate UUID key makes `resolve_slot_id` scan the slot cache (`identity.py:821`).
  - **Measured before the build** (2026-10-29, the orchestrator's stage run on `0ea829e5`): the cost of one `shadow_at` call on CPython 3.12.13, Windows (the Captain's host class), on real objects (an `IdentityService` over a started identity registry, an `AgentStopService`, and a `ShadowRecorder` over a real store with no flusher running). 5 rounds of 20,000 calls after a warm-up; median µs per call: `shadow_at(None, ...)` 0.22; a service with no recorder 3.82; the admit path with a recorder (a system principal) 4.53; an unresolved id (a would-refuse verdict) 5.18, worst round 5.28. It excludes the site's own work and any flush. The measurement of record is #1601 acceptance 7: the persisted `decide` latency per work kind (`latency_by_work_kind`, `p99_bucket`) at the ruling. The whole-call measurement is register R14.
- **D65 Shadow mutates no trust, budget or stop.** T14's allowlists name every import of the package (no trust or budget module). `decide` reads the stop only with `stop_for` (T15). G1 and G2 assert one refusal per seam under the order, so the shadow statements counted none.

class _FailingStore(AdmissionShadowStore):
    """A real store whose first ``failures`` writes call ``during`` (an offer while a write is in flight), then raise."""

    def __init__(self, *, data_dir: Path, failures: int) -> None:
        super().__init__(data_dir=data_dir)
        self.failures = failures
        self.during: Callable[[], None] | None = None
        self.attempts = 0

    async def write_batch(self, boot_id: str, batch: ShadowBatch) -> int:
        self.attempts += 1
        if self.attempts <= self.failures:
            if self.during is not None:
                self.during()
            raise OSError("INJECTED shadow store write failure")
        return await super().write_batch(boot_id, batch)


class _RaisingHandler(logging.Handler):

    def emit(self, record: logging.LogRecord) -> None:

def _certified_crew(rt: ProbOSRuntime) -> CognitiveAgent:
    crew = next(
        (
            a for a in rt.registry.all()
            if isinstance(a, CognitiveAgent) and is_crew_agent(a, rt.ontology)
            and getattr(rt.identity_service.resolve(a.id), "did", "")
        ),
        None,
    )
    assert crew is not None, "premise: the boot has a certified crew agent"
    return crew


async def _run(runner: WorkItemAgenticExecutor, rt: ProbOSRuntime, agent_id: str) -> list[str]:
    """The run entry's answer: ``AgentStopped`` for a stopped agent; otherwise the owned-steps binding error that the
    deliberately incomplete binding raises right after the entry's check, before any run work."""
    try:
        await runner.run(agent_id=agent_id, instructions="i", task_text="t", runtime=rt, owned_steps_execution_port=object())
    except (AgentStopped, OwnedStepsError) as exc:
        return [type(exc).__name__, str(exc)]
    raise AssertionError("premise: the run entry answers before any run starts")


async def _drive(rt: ProbOSRuntime) -> tuple[dict[str, Any], str, str]:
    """Three sinks with no order, then all four under a Captain's stop: the answers, their normalised text and the agent."""
    crew = _certified_crew(rt)
    runner = WorkItemAgenticExecutor(llm_client=rt.llm_client)
    answers: dict[str, Any] = {}
    answers["intent_admitted"] = await crew.handle_intent(IntentMessage(intent=_PROBE, target_agent_id=crew.id))
    answers["tool_admitted"] = (await rt.tool_registry.check_and_invoke(crew.id, _NO_TOOL, {})).error
    answers["run_admitted"] = await _run(runner, rt, crew.id)
    record = (await rt.agent_stops.issue_stop(crew.id, reason=_REASON)).record
    before = rt.agent_stops.refused_counts(record.stop_id)
    intent = await crew.handle_intent(IntentMessage(intent=_PROBE, target_agent_id=crew.id))
    consultation = await crew.handle_consultation_request(
        ConsultationRequest(requester_id="ad1346-m3c1", topic="t", question="q", target_agent_id=crew.id)
    )
    tool = await rt.tool_registry.check_and_invoke(crew.id, _NO_TOOL, {})
    run = await _run(runner, rt, crew.id)
    after = rt.agent_stops.refused_counts(record.stop_id)
    answers["intent_refused"] = [intent.success, intent.result, intent.error, intent.confidence, intent.metadata]
    answers["consultation_refused"] = [
        consultation.responder_id, consultation.answer, consultation.confidence, consultation.reasoning_summary,
    ]
    answers["tool_refused"] = [tool.error, tool.metadata]
    answers["run_refused"] = run
    answers["refusals_counted"] = {seam: after.get(seam, 0) - before.get(seam, 0) for seam in sorted(set(after) | set(before))}

    for value, mark in ((record.stop_id, "<stop>"), (record.sender_detail()["since"], "<since>"), (crew.id, "<agent>")):
        text = text.replace(value, mark)
    return answers, text, crew.id

    """G1 (kills GT-1 to GT-6)."""

    try:

    assert [row for row in disagreements if json.loads(row[-1])["key"] == agent_id] == []

    """G2: #1604 property 12, the golden test (D63)."""
