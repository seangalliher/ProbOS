## 1. Problem

- M3e4a left 28 files `Pending("M3e4c")` in `STORE_WRITE_FILES` (`tests/fixtures/ad1346_store_census.py:100-128`, constant `:38`). WC1 counts them (`tests/test_ad1346_admission_store_census.py:95`) and WC3 pins their owner (`:121`).
- Register R112: M3e4c classifies each one under D218 by reading its writers. Register R113: M3e4d checks what M3e4c finds agent-attributed.
- The writers are listed in §11. Nine files record text or a work product with the id of its author, creator or requester, which the writing function takes from a caller; a production caller passes an agent's id or an HTTP request's value there:
  - `ArtifactStore.add_version` (`artifacts/__init__.py:130`, `created_by` `:138`);
  - `AssignmentService.create_assignment` (`assignment.py:146`; INSERT `:223` with `name`, `created_by` and `mission`); its one caller passes the request's `created_by` (`routers/assignments.py:34`);
  - `CapabilityRequestStore.file_request` (`capability_request.py:736`, `agent_id` and `rationale`);
  - `ClinicalNotesStore.write_note` (`cognitive/clinical_notes_store.py:122`, `author_agent_id` and `body`);
  - `PersistentTaskStore.create_task` (`persistent_tasks.py:176`; INSERT `:225` with `name`, `intent_text` and `created_by`); `routers/scheduled_tasks.py:43` passes the request's `created_by`;
  - `SkillRequestStore.file_request` (`skill_request.py:148`, `agent_id` and `justification`);
  - `ChatThreadStore.append_message_once` (`threads/__init__.py:1380`, `author_id` and `body`);
  - `ChannelManager.create_channel` (`ward_room/channels.py:175`; INSERT `:209` with `name`, `created_by` and `description`); `proactive.py:4906` passes `agent.id`;
  - `WorkItemStore._insert_work_item` (`workforce.py:7704`, `item.created_by` `:7726`). `agent_work.py:607` passes `created_by=member.slot_id`.
- The other 19 files' rows are `System`; D239 gives the class of each file's statements.

## 2. Solution

- **The rows.**
  - The nine files become `Pending("M3e4d")` through one constant, `_AGENT_ATTRIBUTED`.
  - The 19 others become `System(SHIP, reason)`, each reason naming what the file records.
  - `STORE_WRITE_FILES` keeps 76 rows: 9 pending, 66 system, 1 command-line.
- **The table.** `AGENT_ATTRIBUTED_SCOPES` maps each of the nine files to a pair:
  - a (qualified) scope whose SQL write statement records a row D239 makes agent-attributed;
  - the name in that scope of the id the row records as its author, creator or requester.
  - It names one such scope per file, not every one (D240).
- **The tests.**
  - WC1 counts the new kinds.
  - WC3 requires the pending rows to be exactly the table's files, and pins the table.
  - WC5 reads the table against the code: each scope is a point the SQL scan finds in its file, and the first part of its author name is a parameter of the one function of that qualified name in the file.
- **No check.** Nothing is checked, refused or charged. No `src` file changes.

## 3. Decisions (numbered after M3e4b's D228 to D237)

- **D238 The cut** (question 1). This slice classifies the 28 files, and nothing else. The families follow in two slices: M3e4c2 (ChromaDB and JetStream, register R123) and M3e4c3 (file writes, register R124). Then M3e4d (R113): its SQL checks need only this slice; its checks for the families need M3e4c2 and M3e4c3. Then M3e5.
  - Measured volumes:
    - ChromaDB: 24 record writes in 5 files (the calls of section 11 whose first keyword is `ids`), and 4 collection deletes;
    - JetStream: 4 `js_publish` call sites outside `mesh/nats_bus.py`;
    - file writes: 90 hits in 49 files for M3e4a's four primitives, and 104 hits in 46 files for the next group (§11).
  - Ranked:
    1. this;
    2. the families first (new scan code waits on no classification, but the agent-attributed files' checks wait for it);
    3. the 28 files with ChromaDB and JetStream (a second scan design in the same review, and a row for each ChromaDB write scope in five files);
    4. everything at once.
- **D239 The rule** (question 2; applies D218 to rows).
  - A file is agent-attributed when one of its SQL write statements records text or a work product (a body, a rationale, a justification, a description, a mission, a task's intent text, an artifact's content hash, a work item's title and description) together with the id of that text's author, creator or requester, the writing function takes that id from a caller, and a production caller passes an agent's id or a value from an HTTP request there (register R125).
  - The nine files of §1 meet it. Assignments and scheduled tasks meet it as skill requests and clinical notes do, through an HTTP route that sets the id.
  - The 19 others are `System` rows. Their statements fall in these classes:
    - the agent id names the agent or subject the row is about, not an author: the counselor's profiles and assessments (`counselor.py:391`, `:444`), crew profiles (`crew_profile.py:649`), the journal's model-call metrics, chain traces and causal templates (`cognitive/journal.py:408`, `:441`, `:691`; a causal template's `agent_id` is the agent of concern, `causal_reasoning.py:472`, or the synthetic subject `_ship_emergence`, `:435`, `:454`), the ontology prober's results (`self_distillation/prober.py:271`; `raw_text` is the response to the prober's own model call, `:177`, `:202`), and tool fault reports (`fault_report.py:870`; `file_fault_from_turn` passes the agent of the turn that met the fault, `cognitive/continue_or_ask.py:215`, `:249`);
    - the row names agents as its sources: procedures (`cognitive/procedure_store.py:661`, `origin_agent_ids`; `learned_from` is a callsign, `procedures.py:91`);
    - the deciding id is not the author of the row's text: procedures' promotion decisions record `decided_by`, which every production caller passes as `"captain"` (`commands_procedure.py:232`, `:274`; `routers/procedures.py:103`, `:128`); the journal's optimisation proposals record a detector's rationale and the id that decided or applied it (`cognitive/journal.py:524`);
    - the issuer is recorded as a type, not an id: directives (`directive_store.py:40`); every caller of `create_directive` passes `"captain"` or `"counselor"` (§11);
    - the row records no text: standing interests (`cognitive/standing_interest_store.py:60`), the clinical audit log (`cognitive/clinical_audit_store.py:81`), the episode participant index (`cognitive/participant_index.py:96`), fault issue filings (`fault_issue_filings.py:43`), scenario gap links (`holodeck/scenarios.py:423`), and a scheduled task's agent hint (`routers/scheduled_tasks.py:87`);
    - the row has no author, creator or requester column: workflow cron triggers (`cognitive/workflow_cron.py:137`), task sessions and their runs (`task_sessions/__init__.py:236`, `:369`), team simulation records and debriefs (`holodeck/team_simulations.py:544`, `:584`), elastic team specs, slots, attempts and outcomes (`cognitive/elastic_team_store.py:574`, `:581`, `:661`, `:852`), and procedure challenges, comparisons and cycles (`cognitive/procedure_challenges.py:365`, `:440`, `:476`, `:506`);
    - a copy of an agent's state: working-memory snapshots (`cognitive/working_memory_store.py:67`, `:85`).
  - Register R122 holds the writes these classes make `System` although an agent's work produced them.
  - Ranked:
    1. this;
    2. channels, assignments and scheduled tasks `System` under an exception for text that code composes or a request supplies (some of `create_channel`'s in-process callers pass agent ids, `proactive.py:4906`, `capability_request_notifier.py:120`; and the skill-request row, whose id comes only from an HTTP request, is pending);
    3. by caller (an agent-reachable caller makes the file agent-attributed; D218 rejected "every store an agent can reach");
    4. by column alone (any `agent_id` column; that would make the journal's metrics and the counselor's assessments agent-attributed).
- **D240 The rows** (question 2; extends D220 and D221).
  - The nine files are `Pending("M3e4d")`. `AGENT_ATTRIBUTED_SCOPES` names one scope and one author name for each: a scope whose statement records a row D239 makes agent-attributed, which WC5 reads against the code. It does not list every such scope of a file; for example, `ward_room/channels.py`'s `get_or_create_dm_channel` (`created_by=agent_a_id`, `:262`), `artifacts/__init__.py`'s `reconcile_exact_version` (`:204`) and `workforce.py`'s work-item inserts at `:5539` and `:8416` are not in it, and register R113 names more.
  - A file whose row is pending is not split by scope here. M3e4d splits it, as M3e4b split its three files (D229), and gives each scope a row (register R113).
  - The 19 others are `System` rows under `system:ship_computer`.
  - Ranked:
    1. this;
    2. a tuple of (scope, author) pairs per file (a larger pin, and still not every scope before M3e4d's split);
    3. split the nine by scope now (procedure-level evidence for every statement of `workforce.py` and `threads/__init__.py` in a classification slice);
    4. reasons in prose only (no test reads them).
- **D241 The guard** (question 2).
  - WC5 checks each table row against the code, and WC3 pins the table.
  - A new write scope in one of the nine files is noticed when M3e4d splits the file and WC1 compares its scopes.
  - A new write scope in a `System` file is not noticed (register R121).
  - Ranked:
    1. this;
    2. a pinned count of write scopes per file (not measured here);
    3. rows per scope for every file (D220).
- **D242 The families' shapes** (question 3; decided for M3e4c2 and M3e4c3, not built here).
  - **ChromaDB:** an AST scan in the style of `sql_write_scan`.
    - A point is a call whose function is an attribute named `add`, `upsert`, `update` or `delete` and that passes an `ids` keyword, or an attribute call named `create_collection` or `delete_collection`.
    - Rows are per file, with (file, scope) rows where a file mixes, as `STORE_WRITE_SCOPES` does.
    - Blind spots: `ids` passed by position or through `**`, a method reached through `getattr`, and calls of `get_or_create_collection` and `modify`, which the shape does not name.
    - Ranked over an enumerated sites table, and over a guard on `import chromadb`. `perception/backfill.py:108` upserts and is not among the 7 importing files.
  - **JetStream:** an AST scan for attribute calls named `js_publish` outside `mesh/nats_bus.py`, with one row per (file, scope). Ranked over a sites table.
  - **File writes:** a scan of a stated primitive set.
    - The set: `write_text`, `write_bytes`, `os.replace`, `json.dump`, and `open` or `aiofiles.open` with a constant mode that writes; `shutil` copy, move and `rmtree`; `os.rename`, `os.remove` and `unlink`.
    - Rows per file. `RecordsStore.write_entry`, `write_notebook` and `publish` (`knowledge/records_store.py`) are M3e4c3's first candidates for agent-attributed rows.
    - Ranked: 1. this; 2. M3e4a's four primitives only, the rest as register R124's blind spot; 3. the notebooks only (no guard).
- **D243 What a static census does not see** (question 4). Registers R121, R122, R125 and R126.
- **D244 Cost** (question 5). No `src` file changes. The fixture's new table is a module constant built at import, beside `STORE_WRITE_FILES`.

def _parameters(path: str, qualified: str) -> list[set[str]]:
    """The names of the positional-only, positional and keyword-only parameters of each function of ``path`` that is
    reached through class and function bodies, by dotted name."""
    found: list[set[str]] = []

    def visit(body: list[ast.stmt], scope: list[str]) -> None:
        for node in body:
            if isinstance(node, (ast.ClassDef, ast.FunctionDef, ast.AsyncFunctionDef)):
                name = [*scope, node.name]
                if not isinstance(node, ast.ClassDef) and ".".join(name) == qualified:
                    arguments = node.args
                    found.append({arg.arg for arg in (*arguments.posonlyargs, *arguments.args, *arguments.kwonlyargs)})
                visit(node.body, name)

    visit(ast.parse(src_sources()[path], filename=path).body, [])
    return found
